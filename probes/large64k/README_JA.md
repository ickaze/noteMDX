# note.x：64KiB境界の再現用入力

2026-09-26に元MDX2本とLOG8本を受領し、検証を完了しました。追加の返送は不要です。結果は../../docs/LARGE64K_VALIDATION.md、元データは../../tests/large64k_referenceにあります。K00SAFEとK01TAILは改訂2と全バイト一致し、残る6本は原版もエラーでした。以下は原版で再実行する際の手順と、検証設計の記録です。

## 実行

1. このフォルダをX68000の作業用フォルダへコピーしてください。ファイル名は8.3形式、MML・BATはASCII/CRLF、MMLは1行80バイト以下です。
2. note.xが実行できる環境で、このフォルダへ移動します。
3. `RUNNOTE.BAT`を実行します。個別実行する場合は下記のとおりです。

```text
note.x -m256 -v1 -1 K00SAFE.MML > K00SAFE.LOG
note.x -m256 -v1 -1 K01TAIL.MML > K01TAIL.LOG
note.x -m256 -v1 -1 K02PART.MML > K02PART.LOG
note.x -m256 -v1 -1 K03SUM.MML > K03SUM.LOG
note.x -m256 -v1 -1 K04LOOP.MML > K04LOOP.LOG
note.x -m256 -v1 -1 K05LOOP.MML > K05LOOP.LOG
note.x -m256 -v1 -1 K06REPT.MML > K06REPT.LOG
note.x -m256 -v1 -1 K07ESC.MML > K07ESC.LOG
```

`-m256`は書き出しバッファ256KiB、`-v1`はエラー位置付き表示、`-1`は最初のエラーで停止です。**-c/-cn/-zは付けないでください。** #compress/#optも入力にありません。-e/-r/-l/-o/-pも不要です。失敗したときに以前のMDXを結果と取り違えないよう、同名MDXのない作業フォルダで実行してください。

## 各入力で調べること

|入力|通常のMDX格納方法なら予測されるサイズ|目的|
|---|---:|---|
|K00SAFE|56,093バイト|64KiB以内の対照。まずこれが成功することを確認。|
|K01TAIL|67,488バイト|全トラック開始位置・音色領域の開始位置は65535以内。末尾の256音色データを含めたファイル全体だけが64KiBを超える。|
|K02PART|70,093バイト|Aが大きく、B以降のトラック開始位置と音色領域の開始位置が65535を超える。ループなし。|
|K03SUM|96,098バイト|各トラックは約24KiBだが、合計で64KiB超。個別トラックの大きさと開始位置の拡張を切り分ける。|
|K04LOOP|36,094バイト|ファイルは64KiB以内だが、Lへの後方移動が32768を超える。符号付き16bit制限の妥当性を調べる。|
|K05LOOP|70,094バイト|Lへの後方移動も65535を超える。長距離ループの形式を調べる。|
|K06REPT|36,099バイト|有限ループの後方移動が32768を超える。Lとは別の命令形式を調べる。|
|K07ESC|36,301バイト|最終回の/からの前方移動が32767を超える。有限ループ末尾との組合せを調べる。|

上のサイズは**通常形式をそのまま並べた場合の計算値**です。今回K00SAFEとK01TAILについては原版出力と一致しました。残り6本は原版が拒否したため、生成サイズではありません。実際の各計算値・想定オフセットはPROBES.jsonにも記録しています。

音長を増やすだけではデータは増えず、[ ]で同じ短い内容を繰り返してもファイルは大きくなりません。このため、1ステップのcとdを多数直接記述しています。K06/K07もループ内部のMML自体を長くしています。全入力に必要なFM音色を定義し、PDXや追加includeは不要です。

## 改訂2での再実行

```text
notemdx.exe -m256 K01TAIL.MML
```

-mはファイル全体の予算です。K01TAILの音色データ末尾が64KiBを越えることは許容しますが、各開始位置の16bit制限やループ距離は維持します。表の通常形式での計算値のうち、K00SAFEとK01TAILは原版の実測値と一致しました。エラーになった6本の計算値は出力されたファイルサイズではありません。
