# 64KiB境界の検証結果 — NoteMDX 0.8 改訂3（改訂2の結果を含む）

受領・検証日：2026-09-26（日本時間）。large64k.zipに含まれていたMDX2本とLOG8本を使用しました。受領データはtests/large64k_referenceにバイト列を変えずに収録しています。入力は前回送付したprobes/large64kの同名MMLです。

## 結論

**MDXファイル全体を65535バイト以下に制限する実装は誤りでした。** 末尾の音色データを含むファイル全体は64KiBを超えられます。今回のK01TAILは通常の16bit開始位置の形式のまま67,488バイトになっています。

一方、トラック位置が64KiBを超えるK02PART/K03SUMと、長距離ループのK04〜K07は、元のNOTEもエラーにしています。今回の資料に32bit開始位置や長距離分岐の拡張形式は現れていません。任意の大きさの演奏データへ対応できる根拠としては扱いません。

失敗した6ケースにはMDXが含まれていません。エラー行は原版ログの表記です。原版の失敗結果と一致しますが、診断文・行番号・診断数の完全一致を意味しません。特にK07ESCは有限ループ終端で失敗しているため、F4相当の前方分岐だけの限界を独立に確定したものではありません。

ログにはNOTEの版や実行コマンドそのものの表示はありません。依頼時のコマンドはnote.x -m256 -v1 -1でした。原版のエラー復帰処理や、-1指定時の診断数については、このログだけから一般化しません。

## K01TAILの実データ構造

位置は先頭を0としたバイトオフセットです。「データ先頭」はタイトル・CR LF 1A・PDX名終端の後を指します。

|項目|値|
|---|---:|
|MDX全体の長さ|67,488|
|データ先頭のファイル位置|26|
|音色開始位置の16bit値（データ先頭相対）|60,550（0xEC86）|
|音色開始のファイル位置|60,576|
|音色数|256（@0〜@255）|
|1音色の長さ|27|
|音色領域の長さ|6,912|
|A開始位置（データ先頭相対）|20|
|B〜H、Pの開始位置（同上）|60,534 / 60,536 / 60,538 / 60,540 / 60,542 / 60,544 / 60,546 / 60,548|

ファイル長は `26 + 60550 + 256 × 27 = 67488` です。全ての開始位置は16bitに収まっています。音色データはその開始位置から順に並び、各音色の開始位置を追加の16bitポインタに格納する構造ではありません。

@183のレコードはファイル位置65,517〜65,543にあり、その途中で65,536の境界を越えます。ここにも分割マーカーや別形式への切替はなく、通常の27バイト音色が連続しています。最後の@255は67,461〜67,487です。

K00SAFEも通常形式です。データ先頭26、音色開始位置56,040、音色数1で、`26 + 56040 + 27 = 56093` になります。

## 実装修正

- CLIの-mSIZEを、そのままSIZE×1024バイトのファイル全体の予算として使用します。以前の65535への丸めと「形式検証待ち」警告を削除しました。
- 既定予算をnote.docの64KiBに合わせて65536バイトに設定しました。APIのmax_output_bytesも同じ既定値です。CLIは1〜65536KiB、APIは64〜67108864バイトを受理します。
- 各トラックと音色領域の開始位置は、データ先頭から65535以内かを別に検査します。値を下位16bitに切り捨てて続行しません。
- 最後のPCMトラック後にも音色領域の開始位置を検査します。ここで65536以上になる場合、ポインタが折り返す問題を防ぎます。
- ループの符号付き16bit距離の検査は維持します。今回の大きいループを原版も拒否したことを確認しましたが、32767/32768近辺の厳密な境界を原版で追加測定したわけではありません。

```text
notemdx.exe -m256 probes/large64k/K01TAIL.MML
```

K01TAILは既定設定または-m64では予算超過で拒否し、-m66/-m128/-m256では元MDXと全バイト一致します。APIでは `options.max_output_bytes = 256 * 1024;` と指定できます。予算を大きくしても、トラック開始位置やループ距離の制限はなくなりません。

## 検証と再現性

- tests/test_large64k_probes.py：元MDX2本の全バイト一致と構造検査、元ログの拒否結果6本、予算変更時の成否を検査。
- 単体の境界検査：既定予算で65536バイト成功／65537バイト拒否。予算を増やしたとき、音色開始位置65535成功／65536拒否。これは原版の境界測定ではなく、本実装の検査。
- 既存44入力：従来の42本完全一致と2本のEX-PCM補正後一致を維持。実曲11曲を含む。音色・波形バンク2本も一致。
- 今回を含めた52入力：生成成功46本のうち44本が元MDXと全バイト一致、2本はEX-PCM補正後一致。残る6本は元ログと同じ拒否結果。
- 改訂3のLinux/GCC再検証でも同じ結果を確認（rev3_large64k_probes_results.txt）。提供された改訂2のWindowsログではMSVCビルドとlarge64k_probesテストが成功。改訂3のWindows再実行、X68000実機・プレイヤーでの再生は未確認。
