## 実曲11本の追加検証

全11曲が変換・構造検査に通過し、元MDXと全バイト一致しました。STAGE5/6には-c -zを指定し、他9曲は既定設定です。

小規模33入力と実曲11入力を合わせた小計44入力の結果は42本完全一致（STAGE5/6は明示オプションあり）、2本EX-PCM補正後一致です。詳細はIL_VALIDATION.mdとil_results.jsonを参照してください。

## NOTEとの比較

入力MMLはprobes/priority、probes/effects、probes/followup、probes/remaining、参照MDXはtests/referenceです。参照MDXはユーザーから受領したZIPの内容を変更せず保存しています。

|区分|本数|元MDXとの全バイト一致|構造補正後の一致|
|---|---:|---:|---:|
|priority|13|12|1（p11_ex）|
|effects|10|10|0|
|followup|3|2|1（f00_ex0）|
|remaining|7|7|0|
|合計|33|31|2|

p11_exは124バイトから125バイトへ、f00_ex0は90バイトから91バイトへ、比較コピーにのみE8を挿入します。挿入位置はそれぞれ0x32と0x2Dです。元ファイルは保持し、この2本を元ファイルとの全バイト一致件数に含めません。

FMのAパートで音符を発音するf01_ex1では、元のNOTEがE8を出力しており、そのまま全バイト一致しています。

全ファイルの出力SHA-256と照合ログをreference_results.txt、受領した参照ファイルのSHA-256をtests/reference/SHA256SUMS.txtに記録しています。

## 波形エフェクトの検査

AP/DT/TD/VM/MV/KM/TL/YA、ON/OF、モード0/1/2、正負のディレイ、L間隔変更、倍率変更、タイ、休符、qによる無音部分、#reste/#nreste/#cont/#wcmdの組合せを、受領したMDXと比較しました。effectsの10本はすべて全バイト一致しています。

加えて、ループなし波形の最終値保持、DT/TDの合算と片側停止、Q、連符内ポルタメント、TL自動マスク、音程マップの別音色への切替を単体検査しています。g05_mixでNOTEとの全バイト一致も確認しました。

不正・未対応入力として、未定義波形、宣言前の波形定義、不正ループ位置、空波形、範囲外値、未定義キー・マップ、音色定義前のTL、許可されない連符の組合せなどを検査しています。

## バンクとファイル入出力

g00_saveの音色7168バイト・波形131968バイトも全バイト一致しています。g01_loadの検査は、生成したバンクをそのまま使用せず、受領した元バンクから独立に読み込みます。

CLI検査は、日本語パス、文字コード、エラー時の既存MDX保持に加え、バンクの保存／読込、入力上書き拒否、出力名の衝突、不正波形長、複数出力の一時保存失敗時の後始末を確認しています。

## 再実行

```sh
g++ -std=c++17 -Wall -Wextra -Wpedantic -I include src/compiler.cpp tests/test_compiler.cpp -o notemdx_tests
./notemdx_tests
g++ -std=c++17 -Wall -Wextra -Wpedantic -I include src/compiler.cpp src/main.cpp -o notemdx
python3 tests/test_reference.py ./notemdx
python3 tests/test_cli.py ./notemdx
python3 tests/test_il.py ./notemdx
python3 tests/test_statistics.py ./notemdx
python3 tests/test_manuals.py
python3 tests/test_legacy_cli.py ./notemdx
python3 tests/test_large64k_probes.py ./notemdx
```

CMakeではPython3が見つかった場合に、参照比較とCLI検査もCTestへ登録します。Visual Studioの直接ビルドではnotemdx_tests.exeを実行し、参照比較はPythonスクリプトを別途実行できます。

## 構文および0.7で追加した検査

無効な大文字から行末までのコメントと次行の再開、コメント内に不正なy命令やマクロ・括弧がある場合、Sのチャンネル引数、$命令、#/$の不正指定を検査しました。連続臨時記号は通常音符、調号併用、コード、ポルタメント目標で確認しています。通常・音色マクロの閉じ引用符後の説明も検査対象です。

test_il.pyとCTestのil_conversionは、11曲の変換・構造・全バイト一致を検査します。0.7では波形の端数、ループ前のq設定、最適化による値の上書き、LFO未設定状態、パラメータ再利用、オプション優先も検査しました。

## 0.8の追加検査

統計APIでは、有限ループの抜け出しと入れ子、連符、L/Cの範囲、到達しないC、PCM初期バンク・反復をまたぐバンク状態、Cの圧縮境界、極端なループ回数の64bit超過を検査しています。既存44入力の出力比較も維持しています。

## 改訂1の追加確認

表示項目のコロン位置を0始まり12列目で検査し、FM一覧の範囲省略・未使用表示がないことを確認しました。-t/-wの保存先と優先順位、-eの失敗時バンク取得、-rの削除と入力保護、-v1のエラー位置を検査しています。単体ではホストからの保存先指定、進行コールバック、失敗時のrecovery_filesも確認しました。

日英HTML説明書の導入文、スイッチ表、出力例を更新し、日本語導入文の指定内容との一致を検査しています。原版note.docは変更していません。

## 改訂2：ファイルサイズと開始位置の分離

-m256で原版のK01TAILを全バイト再現しました。追加のAPI境界検査は、既定予算の65536バイトで成功・65537バイトで失敗、データ内の音色開始位置65535で成功・65536で失敗、API予算上限の不正値を確認しています。これらの境界値そのものについては原版の実測ではなく、本実装の単体検査です。

全52入力の内訳は、44本が元MDXと全バイト一致、2本が既知のEX-PCM補正後一致、6本は元ログと同じ拒否結果です。音色・波形バンク2本も引き続き一致しています。原版の全エラー回復処理は再現していません。

## 検証の限界

全バイト一致は、記載した設定での対象44入力と2バンクについての確認です。全MML文法・全組合せ・実機での聞こえ方まで検証したものではありません。任意の入力での最適化結果の完全一致は未確認です。NOTEのCLI完全互換とpcmuse.mapは未対応です。対応範囲はCOMPATIBILITY.mdに記載しています。
